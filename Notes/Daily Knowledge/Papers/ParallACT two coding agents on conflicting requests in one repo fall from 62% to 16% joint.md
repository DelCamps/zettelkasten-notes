# ParallACT two coding agents on conflicting requests in one repo fall from 62% to 16% joint

When two independent developers each hand a coding agent their own request on the same code, a single agent given both requests solves 62% of contradictory pairs (Claude Code with Opus 4.8), but two mutually unaware parallel agents solve only 16%. Telling agents a peer exists does not help, and the best messaging setup reaches 32% at 2.23 times the oracle's token cost. Tested on: 155 instances, 7 harness-model configurations across 4 model families, 2 harnesses (Claude Code, Codex).

## Details

**Caveats**
Pairs of agents only; silver split is model-generated by GPT 5.6 Sol; tasks are self-contained diagnostics rather than full team workflows.

**For your work**
If several teams point agents at one repo, don't count on agents talking to each other: serialize hand-offs on shared code, assign an owner for contested modules, and run combined tests after merges.

**Method**
- 155 instances (85 contradictory, 70 complementary): requirement A from SWE-Bench Pro, requirement B a separately motivated counterpart; filters ensure naive merges fail.
- Compares a single-agent oracle against sequential, re-entrant and parallel settings, varying peer awareness and a channel (shared file or Redis inbox), with merge, concatenation or model-based reconciliation.
- Configurations: Claude Code with Opus 4.8, plus Claude Code and Codex with Qwen3.8 Flash Next, DeepSeek V4 Flash and GLM 5.3 Flash; exact McNemar tests.

**Problem**
Coding agents increasingly work in shared repos on independently motivated requests with no central orchestrator. Their changes can each pass their own tests yet conflict when combined.

**Results**
- Parallel-unaware Opus 4.8: 16% contradictory and 57% complementary, vs oracle 62% and 86%; open-weight configs 19% and 53%.
- Redis Sync, the best channel, reaches 32%/77%; a communication oracle that reveals the partner's task reaches 56%/83%.
- Agents send early but read late: only 21-23% of messages are read before the recipient's first edit. A single sequential hand-off recovers much of the gap at similar token cost.
